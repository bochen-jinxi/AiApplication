三、关键决策与说明
--------------------------------------------------------------------------------

1. 为什么改 csproj 的 SDK？
   ─────────────────
   ASP.NET Core 3.1 的 Web 项目必须使用 Microsoft.NET.Sdk.Web SDK。
   该 SDK 会自动引入 FrameworkReference: Microsoft.AspNetCore.App，
   包含 Kestrel 服务器、MVC、Routing、Hosting 等所有 ASP.NET Core 运行时组件。
   若保持 Microsoft.NET.Sdk，则 Program.cs 中的 Host.CreateDefaultBuilder、
   ConfigureWebHostDefaults 等方法将无法解析（编译失败）。

2. 为什么不显式添加 <FrameworkReference>？
   ─────────────────────────────────────
   Microsoft.NET.Sdk.Web 已内置对 Microsoft.AspNetCore.App 的引用，
   手动添加反而会触发 SDK 冲突警告。这是 ASP.NET Core 3.x 的标准做法
   （区别于 2.x 需要显式 PackageReference Microsoft.AspNetCore.App）。

3. 为什么不指定 3.1.32 版本号？
   ───────────────────────
   .NET Core 3.1 的 SDK/运行时版本通过 TargetFramework=netcoreapp3.1 隐式锁定。
   "3.1.32" 是运行时补丁版本号，由本机安装的 SDK 决定，不在 csproj 中显式声明。
   本机当前使用 dotnet sdk 10.0.302 构建（向后兼容构建 netcoreapp3.1 目标），
   运行时需安装 .NET Core 3.1.x 运行时（任何 3.1.x 补丁版本均可运行）。

4. ASP.NET Core 3.1 默认模板代码来源
   ───────────────────────────────
   以下代码来自 `dotnet new webapi` 模板（ASP.NET Core 3.1 版本），
   是微软官方 dotnet new webapi -f netcoreapp3.1 生成的标准内容。
   该模板在 3.1 系列所有补丁版本（3.1.0 ~ 3.1.32）中完全一致，
   因为模板代码只依赖主版本号 3.1 的 API 表面。

四、生成的代码内容
--------------------------------------------------------------------------------

【Program.cs】
    using Microsoft.AspNetCore.Hosting;
    using Microsoft.Extensions.Hosting;

    namespace AiApplication.Api
    {
        public class Program
        {
            public static void Main(string[] args)
            {
                CreateHostBuilder(args).Build().Run();
            }

            public static IHostBuilder CreateHostBuilder(string[] args) =>
                Host.CreateDefaultBuilder(args)
                    .ConfigureWebHostDefaults(webBuilder =>
                    {
                        webBuilder.UseStartup<Startup>();
                    });
        }
    }

说明：
- Main 是应用入口，调用 CreateHostBuilder 构建并运行 IHost。
- CreateHostBuilder 使用泛型 Host（非旧版 WebHost），这是 3.0+ 推荐方式。
- ConfigureWebHostDefaults 默认配置 Kestrel + 路由 + IIS 集成。
- UseStartup<Startup> 指向 Startup 类做进一步配置。

【Startup.cs】
    using Microsoft.AspNetCore.Builder;
    using Microsoft.AspNetCore.Hosting;
    using Microsoft.AspNetCore.HttpsPolicy;
    using Microsoft.AspNetCore.Mvc;
    using Microsoft.Extensions.Configuration;
    using Microsoft.Extensions.DependencyInjection;
    using Microsoft.Extensions.Hosting;

    namespace AiApplication.Api
    {
        public class Startup
        {
            public Startup(IConfiguration configuration)
            {
                Configuration = configuration;
            }

            public IConfiguration Configuration { get; }

            public void ConfigureServices(IServiceCollection services)
            {
                services.AddControllers();
            }

            public void Configure(IApplicationBuilder app, IWebHostEnvironment env)
            {
                if (env.IsDevelopment())
                {
                    app.UseDeveloperExceptionPage();
                }

                app.UseHttpsRedirection();
                app.UseRouting();
                app.UseAuthorization();

                app.UseEndpoints(endpoints =>
                {
                    endpoints.MapControllers();
                });
            }
        }
    }

说明：
- 构造函数注入 IConfiguration，供后续读取 appsettings.json。
- ConfigureServices：注册 MVC Controllers 服务（AddControllers）。
  注意：3.1 默认模板不含 AddSwagger（需额外装 Swashbuckle 包）。
- Configure 管道顺序（重要，顺序敏感）：
    1. UseDeveloperExceptionPage（仅 Development 环境显示详细异常）
    2. UseHttpsRedirection（HTTP → HTTPS 重定向）
    3. UseRouting（端点路由）
    4. UseAuthorization（授权中间件）
    5. UseEndpoints + MapControllers（映射控制器路由）
  这是 ASP.NET Core 3.1 官方推荐的中间件顺序。
