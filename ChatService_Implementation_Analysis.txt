--------------------------------------------------------------------------------
完成以下调用链路的完整实现：

    ChatService
          │
          ▼
    IAiClientProvider
          │
          ├──── OpenAI ────► OpenAiClient

三、核心设计决策与说明
--------------------------------------------------------------------------------

1. 统一抽象 IAiClient
   ─────────────────
   所有厂商客户端实现同一接口 IAiClient，方法签名：
       Task<Result<AiCompletion>> CompleteAsync(
           string model,
           IReadOnlyList<AiMessage> messages,
           double? temperature,
           int? maxTokens,
           CancellationToken ct)
   - 使用 Result<T> 而非抛异常，避免异常控制流。
   - AiCompletion 封装回复内容 + TokenUsage + FinishReason。
   - 每个客户端通过 Provider 属性自报家门（AiProvider 枚举）。

2. 路由器 IAiClientProvider
   ───────────────────────
   AiClientProvider 内部维护 Dictionary<AiProvider, IAiClient>。
   - 构造时注入 IEnumerable<IAiClient>，按 Provider 属性自动建表。
   - GetClient(provider) 查表返回；未注册抛 NotSupportedException。
   - GetClient(AiModel) 重载直接转发到 model.Provider。
   这样新增厂商只需：① 实现 IAiClient  ② 注册到容器，无需修改 ChatService。

3. ChatService 编排流程
   ───────────────────
   ChatAsync(request) 执行五步：
   (1) 参数校验 —— 空请求/空消息直接返回 Failure。
   (2) RAG 检索（可选）—— 调 IRagService.RetrieveAsync 获取知识片段。
   (3) 工具调用（可选）—— 调 IMcpService.ExecuteToolsAsync 获取工具结果。
   (4) 提示词构建 —— 调 IPromptBuilder.Build 组装最终消息列表。
   (5) AI 调用 —— 通过 _provider.GetClient(request.Provider) 路由，
       调 CompleteAsync，封装结果为 ChatResponse。
   RAG/MCP 服务以可选依赖注入（默认 null），未注入时跳过，保持 ChatService
   在最小配置下也可工作。

4. 三厂商协议差异处理
   ─────────────────
   - OpenAI：POST /v1/chat/completions，Bearer 鉴权，messages 含 system。
   - Claude：POST /v1/messages，x-api-key + anthropic-version 头，
             system 是顶层字段（不在 messages 数组中），
             响应 content 是数组 [{type:text, text:...}]，需拼接。
   - DeepSeek：兼容 OpenAI 协议，仅 BaseUrl 与默认模型不同。
   每个厂商有独立的 RequestMapper（静态类）与 ResponseParser（IAiResponseParser 实现），
   协议变化只影响 Infrastructure 层，Application 层无感知。

5. 配置与工厂
   ─────────
   项目未引入 Microsoft.Extensions.DependencyInjection / Configuration 包，
   为保持零外部依赖特性，采用静态工厂 AiClientFactory.CreateProvider(...)，
   传入三个 Options 对象即可得到装配好的 IAiClientProvider。
   若后续接入 DI 容器，可改为注册各客户端为 IAiClient 的多实现，
   AiClientProvider 通过 IEnumerable<IAiClient> 自动收集。

6. 错误处理策略
   ───────────
   - 参数错误 → Error.InvalidArgument
   - 鉴权缺失 → Error.Unauthorized
   - HTTP 非 2xx → Error.ProviderError（含状态码与响应体）
   - 请求超时 → Error.ProviderError（区分用户取消与超时）
   - 未注册提供商 → 抛 NotSupportedException（属编程错误，不应静默）
   所有错误经 ChatResponse.Failure 向上传递，API 层可统一映射为 HTTP 状态码。

六、调用时序示例
--------------------------------------------------------------------------------
用户请求 ChatRequest { UserMessage="你好", Provider=OpenAI, Model="gpt-4o-mini" }
    │
    ▼
ChatService.ChatAsync
    │
    ├─ (RAG 跳过，未启用)
    ├─ (Tool 跳过，未启用)
    │
    ├─► IPromptBuilder.Build
    │       返回 [AiMessage.System("..."), AiMessage.User("你好")]
    │
    ├─► IAiClientProvider.GetClient(OpenAI)
    │       返回 OpenAiClient 实例
    │
    └─► OpenAiClient.CompleteAsync("gpt-4o-mini", messages, ...)
            │
            ├─ OpenAiRequestMapper.Map → JSON
            ├─ HttpClient.PostAsync("chat/completions")
            └─ OpenAiResponseParser.Parse → AiCompletion
                    │
                    ▼
            返回 Result<AiCompletion>.Success(...)
                    │
                    ▼
        ChatService 封装为 ChatResponse.Success(content, usage)

七、后续可扩展点（未本次实现，仅记录）
--------------------------------------------------------------------------------
1. 接入 DI 容器：引入 Microsoft.Extensions.DependencyInjection 后，
   AiClientFactory 可改为 AddAiClients 扩展方法，用 IHttpClientFactory 管理 HttpClient
   生命周期（当前为简单 new HttpClient()，长生命周期可能存在 DNS 老化问题）。
2. 流式响应：当前 CompleteAsync 一次性返回完整内容；
   可新增 IAsyncEnumerable<AiChunk> StreamAsync(...) 支持流式输出。
3. 工具调用闭环：当前 IMcpService.ExecuteToolsAsync 是单次调用；
   完整实现应支持"模型返回 tool_call → 执行工具 → 把结果回填给模型 → 再调用"的循环。
4. 重试与熔断：Infrastructure/Http/HttpResilienceExtensions 已有空壳，
   可接入 Polly 实现指数退避重试与熔断。
5. 单元测试：tests/AiApplication.UnitTests 项目已存在，可为 ChatService 与
   AiClientProvider 编写测试（使用 Moq / NSubstitute 模拟 IAiClient）。
